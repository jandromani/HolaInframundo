# Architecture

## 1. Design goal

GearWatch is intentionally **not** a news summarizer and **not** an LLM stock picker.

The probabilistic layer only discovers and extracts evidence. A deterministic engine decides whether a causal mechanism has moved enough to matter.

```text
web evidence
  -> LLM extraction
  -> canonical JSON
  -> deterministic evidence score
  -> deterministic mechanism state
  -> independent market-data confirmation
  -> Alpha Click gate
  -> read-only dashboard
```

## 2. Anti-alarmism rules

1. One article can never activate a mechanism.
2. Missing data means `UNKNOWN`, never `DORMANT`.
3. `ACTIVE` requires at least two evidence families among physical, pricing and corporate/official.
4. A rumor/social post can create a candidate event, never an activation.
5. Contradictory evidence subtracts from the score.
6. The LLM cannot set the final state or Alpha Click.
7. The market must confirm the thesis before an Alpha Click is emitted.
8. A crowded move is marked `SATURATED`; the system avoids chasing it.

## 3. Evidence families

- **PHYSICAL**: AIS/transits, inventories, production, outages, utilization, deliveries, pipeline flow, lead times.
- **PRICE**: crack spreads, freight/TCE, commodity spreads, yields, FX, physical premia.
- **CORPORATE**: backlog, guidance, capex, bookings, contracts, utilization, procurement targets.
- **POLICY**: central bank decisions, sanctions, tariffs, export controls, procurement rules.
- **MARKET**: equity excess return, relative strength, volume z-score, breadth, gap behavior, revisions/options when available.

## 4. Deterministic mechanism score

Base evidence points are coded, not generated by an LLM:

```text
high-quality physical confirmation       +20
second independent physical confirmation +15
high-quality price confirmation          +15
corporate/official confirmation          +15
policy confirmation                       +10
freshness < 24h                            +5
cross-source agreement                     +5
strong contradiction                     -20
single-source-only penalty                -15
stale evidence penalty                    -10
```

Clamp to 0..100.

Suggested states:

```text
UNKNOWN       insufficient reliable data
DORMANT       0..24
WATCH         25..44
ARMING        45..69
ACTIVE        70..89
SATURATED     causal score >=70 and market crowding >=75
INVALIDATED   explicit invalidation rule satisfied
```

## 5. Market confirmation

The market is treated as distributed intelligence. It does not prove causality, but it votes on whether the thesis is being repriced.

A deterministic market score should use direct market feeds, not LLM judgement:

```text
1d excess return vs sector
5d excess return vs sector
20d relative strength
volume z-score vs 60d
peer breadth
breakout/reclaim vs SMA20/50/200
gap persistence
optional: option IV/skew, earnings revisions
```

## 6. Alpha Click

The system deliberately gives away the first and last euro.

An Alpha Click is eligible when:

```text
mechanism_score >= 70
market_confirmation in [25, 60]
crowding_score < 70
>= 2 independent evidence families
>= 2 independent reputable sources
not invalidated
not already > configured chase threshold
```

Example deterministic score:

```text
alpha =
  0.40 * mechanism_strength +
  0.25 * market_confirmation +
  0.15 * company_exposure +
  0.10 * balance_quality +
  0.10 * catalyst_proximity -
  0.25 * crowding -
  0.20 * structural_risk
```

Weights are versioned and backtested. Every historical signal retains the scoring-version id used at creation.

## 7. Butterfly sensors

The system should search upstream of headlines whenever possible.

Examples:

- **Diesel/refining**: refinery maintenance extensions, export tenders, cargo rerouting, storage draws, crack-spread divergence.
- **Shipping**: AIS route deviations, ballast positioning, insurance premia, charter fixtures, voyage duration.
- **Missiles**: RFQs, appropriations, supplier plant expansion, long-lead component orders, qualification tests, hiring.
- **Rare earths**: customs flows, export licences, physical magnet prices, government stockpile tenders.
- **AI power**: interconnection deposits, project cancellations, transformer orders, utility filings, turbine lead times.
- **Robotics**: paid repeat orders, supplier purchase orders, actuator/reducer lead times, factory utilization, customs/import flows.
- **Japan/rates**: auction tail, bid-to-cover, swap spreads, JGB curve, yen, foreign bond-flow data.

## 8. Memory / Living Bible

There are four durable ledgers:

- `events`: append-only observed facts.
- `mechanism_runs`: every scan and score.
- `predictions`: explicit `IF -> THEN -> deadline` statements with later resolution.
- `company_snapshots`: exposure, balance and market state at each signal.

A compact `living_bible.json` is regenerated from raw history for each mechanism. The LLM sees the compact context plus only recent deltas, not the full history.

## 9. Traceability

Persist for every LLM call:

- generation id
- run id
- mechanism ids
- prompt version/hash
- exact model returned by OpenRouter
- timestamp
- source URLs
- raw response
- parsed response
- token usage / reported cost
- validation errors
- deterministic score before/after

Nothing important should exist only in prose.

## 10. Scan cadence

Do not scan every mechanism at the same rate.

**Tier A — every 6h**
- Hormuz/diesel/refining
- product/crude tanker dislocation
- arsenal / missile supply chain
- Japan / duration
- AI time-to-power
- major geopolitical chokepoints

**Tier B — every 12h**
- rare earths
- aluminium
- counter-UAS
- underwater security
- alternative crude routes
- LNG rerouting
- robotics decoupling

**Tier C — daily**
- humanoid actuator scale
- nuclear fuel sovereignty
- military microreactors
- European strategic autonomy
- structural oil-service CAPEX

This lowers cost and false positives while preserving early detection where information actually moves quickly.

## 11. Cost-control policy

Use an exact free model when available, temperature 0, strict JSON schema and fixed prompt version. Never let the model choose unlimited searches.

For the initial deployment, prefer one fixed Exa-backed web-plugin search per sensor request, then use a verifier only on material state changes.

Budget circuit breakers:

- max scans per day
- max searches per run
- max verifier runs per day
- max daily OpenRouter reported cost
- stop on schema failure loops
- deduplicate identical events before verification

## 12. Website

The website is read-only. It renders:

- mechanism map
- state timeline
- causal graph
- Alpha Click candidates
- company exposure matrix
- event ledger
- prediction ledger
- source trail
- run health/cost

No trade execution is included.
